# QCL 电脑版 1.0.9

Windows 上的 Minecraft Java 版启动器，全中文界面，基于 Electron。**双击安装包即装，无需管理员权限，不依赖任何外部运行库。**

## 下载

- **`QCL-Setup-1.0.9.exe`**（约 130 MB，中文自解压安装程序）← 本 Release 的 Assets
- 仓库：<https://github.com/ALLEN201123/qcl-pc>
- 许可：GNU GPL-3.0

装完在「设置 → 关于」里应显示 `QCL 1.0.9`。装之前请先关掉正在运行的旧版 QCL。

## 本版重点：补上卸载程序

### 之前的问题比想象中严重

安装时注册表里其实**写了**卸载项：

```
UninstallString = "<安装目录>\QCL.exe" --uninstall
```

但 `QCL.exe` **从来没处理过 `--uninstall`** ——
所以在「设置 → 应用」里点卸载，什么都不会发生。这是个死链接。

### 现在点卸载会发生什么

弹出一个**独立的卸载窗口**（不启动主界面），列出三块：

| 项 | 默认 | 说明 |
|---|---|---|
| **程序文件** | 必删 | QCL.exe、resources 等，删掉后无法启动 |
| **游戏数据** | **保留** | 版本 / 实例 / 账号 / 服务端 / 世界存档 / 下载缓存 |
| **本地缓存** | 删除 | Chromium 缓存与运行日志，不影响任何数据 |

每项都显示**完整路径**和**实际大小**（本机实测游戏数据 1.46 GB），路径可选中复制。

**游戏数据默认不勾** —— 里面有你的存档、账号、服务端，误删代价远高于程序本身。

如果你主动勾上「游戏数据」，界面立刻变红：

> 注意：你勾选了「删除游戏数据」。
> 里面包含版本、实例、**世界存档**、账号、服务端配置 —— 删掉之后**无法恢复**。
> 如果只是想重装，请取消这一项。

点卸载时还会**再确认一次**。

## 几个实现上的讲究

### 程序目录最后删，且交给分离脚本

正在运行的 `QCL.exe` **删不掉自己**。所以卸载器写一个临时 cmd 脚本：

- 脚本等主进程退出（`tasklist` 轮询，最多 30 秒）
- 然后 `rmdir /s /q` 删程序目录
- 用 `start /min` 隐藏窗口执行，用户看不到黑框

### 删目录用「先改名再删」

```
GameData  →  GameData.qcl-removing-2026-11-22T10-30-00
```

改名成功的那一刻数据就对用户不可见了；之后即使删除失败（文件被占用等），
也不会留下半删状态，只是留了个带时间戳的目录，重启后可手动删。

### 卸载是独立窗口

卸载时主程序往往已经不完整了（用户可能手动删过文件），
所以卸载界面用内联 HTML + 独立的 preload，与主界面完全解耦，
不依赖 `qcl://` 协议、不加载实例/账号/服务端。

### 一并清理 shell 层

- 注册表 `HKCU\...\Uninstall\QCL`
- 桌面快捷方式（兼容重定向的桌面，如本机的 `D:\桌面`）
- 开始菜单项

|---|---|
| `build/verify-uninstall.js` | **53/53 PASS** — 注册表入口接线、三项清单（路径/大小/说明）、默认策略（程序必删、数据保留、缓存删）、界面文案、**沙箱里真实执行**（删缓存后存档/实例/服务端仍在 → 删数据后确实没了）、程序目录删除脚本会等进程退出且有 30 秒超时 |
| `build/verify-uninstall-ui.js` | **17/17 PASS** — Electron 里真起窗口读 DOM：标题、3 个可勾选项、名称顺序、程序文件勾选且禁用、**游戏数据默认不勾**、勾选后警告出现/取消后消失、取消与卸载按钮、preload 暴露 `qclUninstall.run` |

> 卸载 UI 测试**故意不点「卸载」**：只打开窗口读 DOM 然后杀进程，
> 否则会真删掉本机 1.46 GB 游戏数据。真实的删除逻辑在沙箱目录里单独验证。

## 已知限制

- 目前只打包 Windows x64
- 如果你在卸载时勾了「删游戏数据」，那是**真的删**（有二次确认，不可恢复）
- 程序目录由分离脚本删除，若 30 秒内进程未退出则跳过 —— 此时会提示你手动删除安装目录

详细文档见仓库 [README.md](https://github.com/ALLEN201123/qcl-pc#readme)。
