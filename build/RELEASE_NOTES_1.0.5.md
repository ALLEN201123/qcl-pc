# QCL 电脑版 1.0.5

Windows 上的 Minecraft Java 版启动器，全中文界面，基于 Electron。**双击安装包即装，无需管理员权限，不依赖任何外部运行库。**

- 许可：GNU GPL-3.0

装完在「设置 → 关于」里应显示 `QCL 1.0.5`。装之前请先关掉正在运行的旧版 QCL。

## 本版新增：服务端（一键开服）

入口在**左侧常驻导航栏**，位置在「多人联机」下面。

### 四种服务端核心

| 核心 | 适合 |
|---|---|
| **原版（Mojang）** | 纯净服，最省事 |
| **Paper** | 性能好、支持插件，绝大多数公开服都用它 |
| **Purpur** | Paper 的增强分支，配置项更多 |
| **Fabric** | 要开模组服就选它 |

### 开服前检查（安卓那边要等启动失败才知道）

点「启动」会先检查四件事，有问题当场用中文说清楚：

- **端口**是否被占用（用 `net.createServer` 真绑一次，不是查表格）
- **Java 版本**够不够（按 MC 版本自动挑，本机 10 个 Java 也能挑对）
- **jar** 在不在
- **EULA** 同不同意（会自动弹出确认，同意后写 eula.txt）

Java 映射：`1.16.5↓ → 8`、`1.17~1.20.4 → 17`、`1.20.5+ → 21`、`26.x → 25`、远古 → 8。

### 完整 server.properties（46 项 vs 安卓的 15 项）

安卓 1.6.6 只暴露了 motd / port / gamemode / difficulty / pvp / max-players /
view-distance / online-mode / white-list / enable-command-block / level-name 这几项。
PC 版覆盖 **46 项**，分 5 组并带中文说明：

- **基础**：标语、端口、人数、模式、难度、正版验证、白名单、世界名
- **玩法**：PVP、硬核、飞行、下界、刷怪、村民、命令方块、强制模式、挂机踢出、世界边界
- **世界生成**：类型、种子、结构、视距、模拟距离、tick 超时、出生点保护
- **网络**：绑定 IP、压缩阈值、阻止代理、强制签名、服务器列表、隐藏玩家
- **进阶 / RCON**：RCON 三件套、Query、OP 权限等级、函数权限、实体同步、连锁更新、速率限制、同步写区块、记录 IP

**5 套一键预设**：好友联机（宽松）/ 公开服（严格）/ 创造建筑服 / 硬核生存 / 低配省性能。

写入时**保留原文件的注释与顺序**，玩家手改过的内容不会被覆盖；未知键也原样保留。

### RCON（安卓没有）

开 RCON 之后，即使控制台关了也能管服务器：

- 查在线玩家（解析 `list` 命令成结构化列表）
- 发任意命令（op / gamemode / time / weather / gamerule…）
- 全服广播
- 踢人、设 OP、重载白名单
- 「一键开启」自动生成密码；端口被占自动换一个

实现的是标准 Source RCON 协议（包解析支持粘包、半包、认证失败 id=-1、哨兵包判结束）。

### 备份 / 恢复 / 导出（安卓完全没有）

- **手动备份**世界，或**全量备份**（含 mods / config / plugins）
- **定时自动备份**：可设间隔（分钟）与保留份数，自动轮转（保留最新 N 份）
- **恢复**：先把当前世界改名留底（`world.old-时间戳`），再解回备份；解压失败自动回滚
- **导出 zip**：一键打包并在资源管理器里定位
- **备份前先让服务端保存世界**（`save-off` → `save-all flush` → 备份 → `save-on`），
  否则会拷到写一半的区块 —— 这是最容易踩的坑，已处理

### 崩溃诊断

启动失败不是只丢一串英文，而是给中文结论：

> 端口被占用 / 没同意 EULA / Java 版本过低 / 内存不足 / 模组或插件不兼容 /
> 连不上 Mojang 验证 / jar 损坏 / 世界文件损坏

并挑出日志里最关键的那几行（`Exception` / `Caused by` / `at ...`），方便复制反馈。

### 进程管理

- **优雅停止**：先发 `stop` 让服务端保存世界，等 30 秒；超时才强杀
- **强杀用整棵进程树**（Windows `taskkill /T /F`），不留孤儿进程占着端口
- **可选自动重启**：崩溃后自动拉起，可设次数上限
- 多个服务端可同时管理，各自独立目录

### 修的两个真实问题（都是实测踩到的）

1. **服务端日志中文全是乱码** —— Java 在 Windows 上往管道写 stdout 时用系统代码页（GBK），
   而 Node 按 UTF-8 解码。修法：给 Java 加 `-Dsun.stdout.encoding` / `-Dstdout.encoding`
   等五个参数，并在解码侧加 GBK 兜底重解。
2. **进程退出时主进程崩溃**（`ERR_STREAM_WRITE_AFTER_END`）—— `exit` 里先 `end()` 日志流、
   随后又 `emit` 退出日志，往已关闭的流写入会抛未捕获异常。修法：先 emit 完再 end，
   并给流挂 `error` 监听。

## 已知限制

- 目前只打包 Windows x64
- 原版核心：`1.2.5` 及更早 Mojang 没发服务端 jar，会提示改用 Paper
- Paper/Purpur 只能装它们支持的那些 MC 版本（会明确提示版本不存在）
- 26.x 及部分 1.21.x 官方尚未发布 OptiFine（与启动器侧一致）

详细文档见仓库 [README.md](https://github.com/ALLEN201123/qcl-pc#readme)。
