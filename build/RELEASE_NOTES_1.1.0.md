## 本版重点：修微软账号「假过期」

你报的现象：**主界面说账号过期了，但账号明明还能用。**

这是真 bug，而且根子上是判断逻辑错了。

### 错在哪（两层）

**① 到期时间被我写死了 12 小时**

```js
// 原代码
// 微软令牌默认 24 小时有效，这里保守记 12 小时
expiresAt: Date.now() + 12 * 60 * 60 * 1000,
```

而微软服务端**实际返回**的是 `expires_in = 86400` 秒（24 小时）。
于是一登录满 12 小时，界面就开始谎报「登录已过期」。

**② 更根本：access token 过期 ≠ 账号失效**

微软的 refresh token 有效期是**几个月到一年**。只要它在，access token 随时能换新的 ——
账号一直是可用的。但我以前只看 `expiresAt`，一个陈旧的过期时间就永远显示「已过期」。

**③ 而且以前根本没有续期通道**

自动续期只在「启动游戏」时才触发。所以主界面从来没机会把过期令牌换成新的，
那个假警报就一直在那儿。

### 改成了什么

| 项 | 改前 | 改后 |
|---|---|---|
| 到期时间来源 | 写死 12 小时 | **服务端 `expires_in`**（真实值），拿不到才退到 24 小时 |
| 界面判定 | `expiresAt < now` 就说过期 | **有 refreshToken 就一律正常** |
| 续期时机 | 只在启动游戏时 | 加载账号后**后台静默续期**（不阻塞、失败不打扰） |
| 提示文案 | 「登录已过期」 | 只有连刷新令牌都没了才提示重新登录 |

### 对齐了 HMCL 的做法

翻了 `vendor/HMCL-latest` 的源码确认：

- `MicrosoftService.java` L148：`notAfter = expiresIn * 1000L + now` —— **直接读服务端 `expires_in`**
- `MicrosoftAccount.logInWhenCredentialsExpired()`：过期就**静默刷新**，刷新失败才提示

**HMCL 从不把「令牌过期」当作界面上要展示的徽标。** 我们之前反着做，所以错了。

### 实测（用本机真实账号）

```
续期前 expiresAt = 2026/11/7 19:55   ← 早就过了，界面显示已过期
续期后 expiresAt = 2026/11/24 21:40
expiresInSec     = 86400             ← 服务端真实值，不是我猜的
界面状态         = 正常
```

## 本版同时包含上一版的卸载程序

「设置 → 应用」里卸载会弹出独立窗口：

| 项 | 默认 | 说明 |
|---|---|---|
| **程序文件** | 必删 | QCL.exe、resources 等 |
| **游戏数据** | **保留** | 版本 / 实例 / 账号 / 服务端 / 世界存档 |
| **本地缓存** | 删除 | Chromium 缓存与日志 |

勾选删游戏数据会有红色警告 + 二次确认。程序目录交给分离脚本删除（运行中的 exe 删不掉自己）。

## 已知限制

- 目前只打包 Windows x64
- 如果 refresh token 本身失效（长期未用、改过密码、账号异常），仍需要重新登录一次 —— 这时界面才会提示
- 静默续期需要联网；断网时保持原有状态，不报错

详细文档见仓库 [README.md](https://github.com/ALLEN201123/qcl-pc#readme)。
